# モバイル・フォーム・LINE・決済・表示速度

Playwright/Chromium を iPhone相当（幅390px、ja-JP、Asia/Tokyo）で走らせ、
computed style で実測（31件）。

## モバイル比率：BtoCとBtoBで設計強度を変える

- 個人のインターネット利用は端末別で**スマートフォン74.4%がパソコン46.8%を27.6ポイント上回る**
  （2024年、総務省 令和7年版情報通信白書）
- 物販系BtoC-ECの**スマートフォン経由比率は61.7%**（経産省調査の報道）
- **BtoBは拮抗**：購買・導入決定関与者445名のうちスマートフォンで企業サイトを閲覧したのは
  49.7%、閲覧しなかったのも49.7%（2018年10月調査、やや古い）

**BtoC LPはモバイルファースト、BtoB LPはモバイル「も」必須。** 設計強度に差をつける。

## 固定追従CTA：測定法で5%から87%まで割れる

**単一の全国値は出せない。** 4つの測定が食い違っているが、これは矛盾ではなく標本と定義の差。

| 標本 | 追従CTAあり | 測定法 |
|---|---|---|
| デザイン評価軸含むCV目的LP（n=42） | 2/42（5%） | Playwright computed style、`position:fixed/sticky` のCTAに限定 |
| 広告配信型（n=55） | 13/55（23.6%） | Chromium実機＋スクリーンショット目視 |
| ギャラリー掲載型（n=32判定可） | 18/32（56.3%） | HTML取得ベース（下振れの可能性あり） |
| 大手広告主の指名標本（n=31） | 27/31（87%） | Playwright実機、上部固定ヘッダーも含む広い定義 |

**したがって「モバイルLPは追従CTA必須」は通説として扱い、母集団と業種で判断する。**

- 記事LP：**0/17（0%）**。記事の没入を切るため意図的に外している。
- 医療・クリニック：**6/7**。突出して多い。
- BtoB SaaS：下部バーを使わず**上部固定ヘッダー型**が主流。
- 全体として、ページ内にCTAを反復配置（中央値7回）することのほうが普遍的。

### 実装する場合の実測値

| 項目 | 実測値 |
|---|---|
| 形式 | 下部全幅固定バー11件／CTA内包の上部固定ヘッダー8件／右下フローティング2件／なし4件 |
| 高さ | 中央値**83px**（最小48px＝chocoZAP、最大96px＝北の快適工房） |
| 幅 | 10/11件が100% |
| 文言 | 動詞＋（無料 or 所要時間） |
| 表示タイミング | FVから常時7件 対 スクロール後出現5件 |

**デフォルトはスクロール後出現にする。** FVには本体CTAがあるため、追従バーはFVを塞ぐだけに
なりやすい。出現位置は35%地点または75%地点の実装が観測された。

### 実在する事故：Cookie同意バーとの衝突

プレミアムウォーターは下部88pxの追従CTAとは**別に**Cookie同意バー（高さ248px、z-index 99999）が
下部を占有しており、35%地点・75%地点の両方で追従CTAが同意バーに覆われていた（実測）。

**下部固定CTAを置くなら、同意UI・チャットウィジェット・戻るボタンとのz-index衝突を
実機で必ず確認する。**

## フォーム（EFO）

### 3点セットは差別化ではなく前提条件

**郵便番号からの住所自動入力・ふりがな自動入力・全角半角自動変換。**

国内EFOツールが揃って標準搭載している（EFO CUBE は26機能、GORILLA EFO は20種類以上として
公式に掲載）。これが無いフォームは日本市場では単に不備。

### 効くのは項目の削除であって必須・任意の切り替えではない

WACULのB2Bサイトフォーム調査：入力項目数と通過率に強い負の相関があり
**「1項目減らすと通過率は約2ポイント向上」**、平均通過率は20.37%（最大34.40%）。
同調査は**「必須にしても任意にしても通過率は変わらない」**とも報告している（二次、2019年）。

### 実測されている項目数

| 種別 | 実測レンジ | 備考 |
|---|---|---|
| BtoB 資料ダウンロード | 7から8項目 | クラウドサインは会社名・姓・名・メール・部署・電話・導入における立場の7項目 |
| BtoB デモ・トライアル | 11から12項目 | |
| BtoB 問い合わせ | 8から14項目 | SmartHRは**14項目全必須** |
| 住宅 カタログ請求 | 14から49項目 | 桧家住宅が全49（必須12） |
| 一括見積もり | 3から4ステップに分割 | 番号付きインジケーター付き |

国内の二次情報が示す「トライアル3から5項目、デモ5から7項目」よりも**実測値は一貫して多い**。
理想値ではなく実勢を知った上で、意図的に減らす判断をすること。

### 見せる項目を減らし、非表示で埋めるのが日本のエンタープライズ実装

SmartHRのMarketoフォームには**非表示27項目**が仕込まれている：
utm_source / medium / campaign / content / term、gclid、および `stande_` 接頭辞の企業属性14項目
（上場区分・URL・売上・従業員数・本社フラグ・業種・資本金・郵便番号・都道府県・市区町村・
住所・電話・法人番号）。ferret One も非表示13項目（法人名読み／法人番号／郵便番号／所在地／
従業員数／インボイス登録番号）を持つ。

**ユーザーに聞かずに企業データベースで補完する**設計が標準。ただし取得する情報が増えるほど
個人情報保護法上の利用目的の明示範囲も広がる（[`legal.md`](legal.md) E節）。

### 法令上の必須事項

- **利用目的をフォーム送信前に明示する。** フッターのプライバシーポリシーへのリンクだけでは
  個人情報保護法21条2項を満たさない（書面・電磁的記録による直接取得では「あらかじめ、本人に
  対し、その利用目的を明示しなければならない」）。
- **リードを提携先・代理店に渡すなら同意が要る**（27条1項）。一括見積もり型は特に注意。

副次所見：保存134ファイル中、GTMは112件検出に対し**Cookie同意基盤（CMP）はわずか4件**。
タグは入れてもCMPは入っていないのが日本のBtoBサイトの実勢。ただし日本で必須なのは
Consent Mode v2 ではなく電気通信事業法の外部送信規律であり、**その規律も自社商材を売る
通常のLPには原則かからない**（[`legal.md`](legal.md) E節、[`ad-platforms.md`](ad-platforms.md)）。

## LINE導線

日本固有の強い導線。ただし**計測が難しいことを前提に設計する**。

実測では、トップ階層に友だち追加導線があったのは31件中6件のみ。**BtoB SaaSは0件。**
医療脱毛・転職では主要CVとして使われている（エミナルクリニック `line_friend.php`、
WORKCANVAS `/lp5/enquete`）。

### 計測は二重構えが必須

1. **`lin.ee` へ遷移した時点で別ドメインに移るため、UTMやgclidはLINE側に引き継がれない。**
2. 公式側の受け皿は「友だち追加経路（経路／流入元／キャンペーン）」パラメータだが、
   **各パラメータで20回以上の流入がないと数値が表示されず「その他」に集計される**
   （LINEヤフー for Business 公式マニュアル）。
3. したがって：**LPの友だち追加ボタンのタップをGTM等でCV送信し、精度検証をLINE側の
   追加経路で行う。**

### LINEログイン併用時

`bot_prompt=aggressive` が最も確実。`normal` は同意画面に友だち追加オプションを表示するだけだが、
`aggressive` は同意画面の後に専用の確認画面を表示する。追加が起きたかは
`friendship_status_changed`（true / false）で判定でき、`/friendship/v1/status` でも照会できる
（LINE Developers 公式）。

## 決済

**クレジットカード＋コード決済（PayPay）が最低ライン。**

EC決済手段（物販）：クレジットカード67.3%、PayPay 30.4%、Amazon Pay 14.9%
（GMOペイメントゲートウェイ調査 2025年9月、n=6,556、二次）。

そして**よく利用する決済手段がない場合、56.5%以上がそのサイトを離脱する**
（SBペイメントサービス 決済手段のEC利用実態調査2025年度版、物販n=2,455、二次）。

カゴ落ち率は**63.48%**（2026年上半期、2,250サイト、二次）。

**LP一体型カートはこの遷移離脱を構造的に潰す設計。** 単品リピート通販カート（ecforce、
リピスト、たまごカート等）はフォーム一体型LPと確認画面スキップを機能として持つ。
広告配信型の実測でも `https://ドメイン/lp?u=キャンペーンID` 形式（ecforce系と思われる）が多く、
Amazon Pay ログインボタンをフォーム冒頭に置いて入力自体を飛ばす設計も複数あった。

**ただしフォーム一体型は特商法12条の6の最終確認画面規制と直結する。**
そのフォーム画面自体が最終確認画面に該当しうる（[`legal.md`](legal.md) B節）。

## 表示速度：日本語Webフォントが最大の単一要因

**Noto Sans JP フルセットは1ウェイトで1.5から2MB規模。** 英字フォントと桁が違う。

国内事例で、3ウェイト6.05MBのWebフォントを整理して Speed Index 3.3秒から1.7秒（48%改善）、
別事例で LCP 2.8秒から0.2秒という改善が報告されている（二次）。

**LPは文言が固定されるため、サブセット化の効果が最大化する。** 原則は次のいずれか：

1. 使用文字だけのサブセットを生成する（LPは文言が確定しているので完全に可能）
2. システムフォントを使う（`"Hiragino Sans", "Yu Gothic", sans-serif`）
3. 見出しだけWebフォント、本文はシステムフォント

**フルセットのWebフォントを3ウェイト読み込むのは、日本語LPで最もありがちなLCP破壊。**
