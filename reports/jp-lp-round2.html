1. このレポートの位置づけ

これは訂正報告である 第1次調査の結論を第2次調査で反証にかけた結果、初版の看板だった発見を含む15項目を訂正した。初版のレポートを読んだ人は、この文書で差分だけを把握できる。

訂正の方向はほとんどが「より慎重な側」である。断定していたものを解釈に格下げし、母集団と呼んでいたものを連続分布に改め、「1件は存在する」としていたものを「使えるものは0件」に厳しくした。

1.1 なぜ再調査したか

第1次調査では、指定ツールだった Perplexity API が全レーンで HTTP 401（クォータ超過）を返し、一度も使用できなかった。代替として WebFetch・e-Gov法令API・ヘッドレスブラウザ・pdftotext で調査を完遂したが、到達できなかった一次資料が22項目残った。

APIキーの差し替えで Perplexity が復旧したため、12レーンで再調査した。ただし同一条件の再実行はしていない。実測ベースの結論（和文タイポの実測値、CTA寸法など）は同じ手法で測れば同じ数字が出るだけなので、火力を次の3点に集中した。

  1. 第1次で埋められなかった穴
  2. 主要結論の反証（追認ではなく、壊しにいく専任レーンを置いた）
  3. 依頼主が実際に出稿している Google / Meta の2媒体への最適化

1.2 証拠プロトコルを1点強化した

Perplexityの回答をそのまま「公式」にしない 返ってきた出典URLを WebFetch で開き、原文を確認できたものだけを一次情報として扱う。開けなければ弱いラベルのまま残す。要約は結論ではなく原典への地図として使う。

この運用は機能した。12レーンのうち少なくとも5レーンが、Perplexityの誤りを実地で検出している。

  • 提示URLが404、または別法令（いじめ防止対策推進法）へ転送された
  • 調査時期が半年ずれていた
  • キャッシュレス比率を58.5%と回答（実際は58.0%）
  • ステマ規制の確約4件を「措置命令」と誤記
  • ABテストの「事例」として、架空のサンプルサイズ設計例を提示した

要約をそのまま採用していれば、これらは成果物に入っていた。

2. 最も重い訂正：「2つの母集団」は成立しない

初版は「日本のLPは統計的に別物の2母集団に分かれる」と書き、これを最大の発見として提示した。この言い方は支えられない。

2.1 4つの理由

#問題内容
1サンプリング枠が重なっている「ギャラリー」として扱ったLPアーカイブ（rdlp.jp）は、公式に「広告をクリックした際に表示されるランディングページ」を集めると明記しており、fbclid付きの記事LPが実際に登録されている。2群は互いに素ではない
2測定手法が非対称で中立でない一方はHTML取得ベース、他方はスクリーンショット目視。初版が別途「日本のLPは装飾を画像に焼き込む」と結論している以上、HTML側は構造的に装飾を取り逃す。この2つの発見は並置できない
3キュレーションが入っているLPアーカイブの掲載基準は「弊社で良いと思ったデザイン」という主観選定。母集団統計ではない
4件数の読み違い「46,006件」は登録総数ではなくPCデザインの表示件数。登録総数は2025年3月時点で約7.6万件

2.2 訂正後の結論

装飾濃度は連続的に分布する 位置を決めるのは業種ではなく、(1) 誰が作ったか（ブランド本体かDR事業部か）、(2) どの制作SaaSを使ったか、(3) どの面に配信するかの3つ。

設計に入る前にこの3つを確定させる。「日本のLPの型」という単一の答えを探さない。

なお差の向きそのものは実務者の認識と整合しており、数値は取り下げていない。取り下げたのは「境界のある2集団」という枠組みである。数値を引用するときは上記4つの交絡を必ず添える。

3. 「記事LP」は市場の型ではなくベンダーの処方だった

初版は /ab/ というパスを「記事LPのパス」として一般化した。これは Squad beyond というツールのホスティング規約である。n=17 は1ベンダーの標本にすぎない。

そして赤字・黄色マーカー 17/17（100%） という数字は、同社が公式ブログで「太字＋マーカー」「吹き出しを多用」と処方した結果だった。市場が自然にそこへ収束したのではない。

規模感は無視できない Squad beyond は自社システム製ページが年間推定9,000億円（国内ネット広告媒体費の約30%相当）の広告配信に使われていると自己申告している。初版が「日本の広告LPの型」と呼んだものの相当部分は、単一SaaSのテンプレート効果である可能性が高い。

3.1 ただしベンダー差は媒体差の「実装手段」でもある

同じレジーナクリニックが、Googleには自社公式LP、MetaにはSquad beyond系の記事LPを当てていることが実測で確認された。Google側18件では sb- ドメインも /ab/ パスも0件、Meta側51件では23.5%と29.4%。

つまりベンダー差と媒体差は対立しない。媒体ごとの狙いを実装する手段としてベンダーが選ばれている。

5. コピー理論：3つの通説が覆った

5.1 PASONA 問題の決着

初版は、著者公式サイトの表記（新・PASBECONAの法則）と二次情報（新・PASONAの法則）が食い違うため保留とした。決着した。

  • 2016年『稼ぐ言葉の法則』は「新・PASONAの法則」が正。国立国会図書館の書誌（納本現物由来）2件が一致し、ダイヤモンド社の発売日記事も本文・見出しとも一致
  • 著者公式サイトの PASBECONA 表記は、サイト全体の文字列一括置換の産物。決め手は内部矛盾で、同ページが「17年前に開発したPASBECONAの法則」と書いているが、17年前＝1999年に PASBECONA は存在しない。置換痕は著者会社サイトの別2ページでも実測された
  • PASBECONA は実在するが2021年の別書籍（『コピーライティング技術大全』）。9要素は Problem / Affinity / Solution / Benefit / Evidence / Contents / Offer / Narrow down / Action

実務判断：2016年書籍を参照するなら「新・PASONA」、2021年書籍なら「PASBECONA」と年で分ける。「1999年にPASBECONAを提唱」は著者側サイトの記述であっても誤り。

5.2 AIDMA をホールに帰属させてはいけない

岸志津江（東京経大学会誌326号）が Hall の原著5冊を直接検証し「AIDMAの5文字は見当たらなかった」と結論している。Hall が実際に用いた型は AICCA（1915）。

AIDMA は日本で広まった通説である。提案資料で「ホールが提唱した AIDMA」と書かない。

5.3 「漢字率3割が読みやすい」は実験で否定されている

杉山・小田（2015、日本心理学会第79回大会）は、読みやすさは漢字要因では説明されず、むしろ漢字率を下げると「子ども向け」という印象が出ることを報告している。可読性に効くのは漢字率ではなく漢字の連続長。

実務判断：「漢字率3割に抑える」という指針を使わない。代わりに漢字が長く連続する箇所を割る（読点、ひらがなの接続語、改行）。

6. Google と Meta の配信構造に合わせるLP設計

依頼主が実際に出稿しているのは Google と Meta の2媒体である。初版は「審査に落ちない要件」しか押さえておらず、配信構造に合わせた設計がまったく無かった。今回の最大の新規追加である。

6.1 最初の分岐は「温度」ではなく算数

LPを分ける前に確認する 月間予算 ÷ 許容CPA < 30 なら、LPを分けない。まず中間CVを1枚に足す。

Googleのスマート自動入札は「1か月以上の期間に30回以上のコンバージョン」を推奨（tROASは50回以上）。この水準に届かない案件でLPを増やすのは、少ないデータをさらに割る自傷行為になる。

なお GoogleとMetaでLPを2枚に割っても学習データは分割されない（アカウントが別のため）。分けるコストは制作費と計測実装費だけ。危険なのは同一媒体内でLPを増やすほうである。

6.2 Google：前提が壊れている点が2つ

最終ページURLの拡張はデフォルトでオン P-MAXでは、オンの間Googleが入稿したLPを無視してドメイン内の別ページへ送る。つまりLP設計の対象は「作った1枚」ではなくドメイン全ページになる。LPが1枚しかないなら、公式が明示的にオフにするよう書いている。

さらに2025年以降、同じ拡張が検索キャンペーンにも来た（AI最大化設定を有効にするとデフォルトで有効）。「検索広告なら指定したLPに着地する」という前提はもう成立しない。

もう1点。拡張がオンのとき、LP上の画像がGoogleに取り込まれて広告アセットとして使われる。LPは遷移先であると同時に素材倉庫になる。画像の利用許諾が広告利用まで及んでいるか、焼き込んだ文言が単独で流通しても薬機法・景表法に耐えるかを、LP側で先に潰す必要がある。

品質スコアについて言えること・言えないこと

よくある言い方実際
品質スコアが上がるとCPCが下がる1から10の数字はオークションに入らない。公式に「診断ツール」と明記
LPを直せばCPCがX%下がる公式には言えない。ただし「ランディングページの利便性」は広告ランクに入り、広告ランクが実際のCPCを決めるので経路は追える
Core Web Vitalsを満たせば広告評価が上がるCWVの閾値はGoogle広告側の基準ではない。SEOの話と混同しない

「ランディングページの利便性」の判定要件リストは公式に存在しない（旧記事はリダイレクト済み）。要件表を作って「これを満たせば高得点」と提案してはいけない。

6.3 日本のLPで最も多い計測事故

サンクスページに「送信完了しました」しか出さない設計 これだと拡張コンバージョンの自動収集もCSSセレクタ指定も空振りする。対処はメールアドレス等をDOMに出すか、dataLayer.push() のコード方式に切り替えるか。

実装上の要点：

  • フォームの各 input に id を付ける
  • 姓と名を2フィールドに分ける（別フィールド仕様のため）
  • hidden に gclid / gbraid / wbraid を3つ別々に持つ
  • gbraid は大文字小文字が区別されるので小文字化しない
  • click_time と order_id をCRMまで引き回す
  • ハッシュ化はブラウザ側で自動。LP側で事前ハッシュ化は不要

6.4 Meta：LPを触ると学習は壊れるのか

公式の significant edits 一覧に「LPの内容変更」は無く、「Any change to ad creative」はある。

  • 同一URLのまま中身を書き換える → 学習はリセットされない
  • リンク先URLを切り替える → 踏む

したがってLPはURL1本に固定し、訴求軸はFVブロックの内部出し分けで処理する。A/Bを広告側でURLを振って回すのは学習を壊す。

6.5 個人的属性ポリシーの正しい直し方

初版は「『あなたも◯◯でお悩みでは？』型が該当し得る」とだけ書いた。これでは直しようがなかった。公式のDo/Don't原文の対比が決定的だった。

可不可
Meet seniorsMeet other seniors
Depression counselingDo you have diabetes?
禁止されているのは属性への言及ではない 「広告主が読者の属性を知っていると示唆すること」が禁止されている。したがって消すべきは「あなた」そのものではなく、"other" 相当語と二人称疑問形。属性の帰属先を読者からサービス・市場へ移せば通る。訴求を捨てる必要はない。

また Advantage+ audience で拡張されない項目は「地域・最低年齢・言語・除外カスタムオーディエンス」の4つのみで、詳細ターゲティングは拘束力を持たない。「40代女性に配信しているはず」という前提でFVを書くと外れる。FVは属性ではなく「場面」で名乗らせ、属性による絞り込みはLP中盤に置く。

6.6 インスタントフォーム vs LPフォーム

既定はLPフォーム。インスタントフォームはLP側のイベントが1件も発生せず、external_id の発行がMeta離脱後になる。つまりLP資産にもEMQにもGoogle共用にも一切寄与しない。使うのは検証と立ち上げ期の暫定に限る。

日本でのCPL差・商談化率差の数値は、母数を示した出典が皆無だったため採用していない。「インスタントフォームはCPLが安いがリード品質が低い」という定説の定量的裏付けは見つかっていない。

6.8 どこを分け、どこを揃えるか

分ける価値が高いのはFVの入り方 Google側は「答えから始める」（公式が重要な情報のページ上部配置を要求）。検索で言語化して来た人に共感の前置きは冗長。
Meta側は「場面・問題提起から始める」。フィードに割り込んでいるので、なぜ自分に関係あるのかを先に立てる必要がある。

1枚で兼用すると、この2つがFVの同じ場所を奪い合い、必ずどちらかが妥協する。

逆に揃えるべきもの：サンクスページは1本に統合する。event_id はLPテンプレート側で採番する。そしてCVRの分子は媒体管理画面の合計ではなくGA4/CRMの実CVに固定する（両媒体が同じCVを自分の成果として報告するため、合計すると必ず水増しになる）。

原典PDF（2024年版）と現行Web版で章番号が1つずれている（Yahoo!きっずの章が消滅）。チケット不正転売の禁止追加、士業への懲戒処分条項追加など、Web版のみの更新が10件ある。PDFを一次資料として引用すると古い内容を引くことになる。

8. 2026年の環境変化

8.1 景表法の執行スタイルが変わった

指標推移（3年）
措置命令44件 → 26件 → 13件（約70%減）
指導85件 → 339件 → 388件
確約認定0件 → 1件 → 8件
ステマ告示令和7年度は措置命令ゼロ（確約4件＋指導7件）

初版は「措置命令は公表されるので報道インパクトが大きい」と書いたが、実態は確約と指導で処理される方向にシフトしている。ただし直罰と課徴金の条文は生きているので、リスクが消えたわけではない。

8.2 個人情報保護法に初の課徴金制度

令和8年改正個人情報保護法が2026年7月17日公布。LPの計測タグとフォームが射程に入る。施行は政令待ちなので、現時点は監視対象。

8.3 Cookie についての誤解を正す

サードパーティ Cookie は残る 2025年10月17日に廃止が発表されたのは Privacy Sandbox の広告系API 10本であって、Cookie自体ではない。Chromeは "maintain our current approach to offering users third-party cookie choice" と明記している。

つまり「Cookieの移行先」として用意されていたものが先に消えた。Cookie消失を前提にした設計は不要である。

8.4 LP制作の単価環境

インターネット広告費は4兆459億円（前年比110.8%、構成比50.2%で初の過半数）だが、制作費は4,922億円で104.0%と媒体費の111.8%に7.8ポイント劣後している。LP制作の単価環境は悪化方向である。ただしAIとの因果を示す調査は存在しない。

9. 明日から何をするか

今回の発見を、依頼主の運用（Google＋Meta、日本市場）に落とした行動リスト。

9.1 すぐ確認すべきこと

  • P-MAXを使っているなら、最終ページURLの拡張の設定を今すぐ見る。デフォルトでオンなので、意図せずドメイン内の別ページに送られている可能性がある。LPが1枚しかないならオフにする
  • 検索キャンペーンでAI最大化設定を使っているか確認する。同じ拡張が効く
  • サンクスページにメールアドレス等がDOMに出ているか確認する。「送信完了しました」だけなら拡張コンバージョンが空振りしている
  • gbraid を小文字化していないか確認する
  • Meta広告のLPをURL単位でA/Bしていないか確認する。していたら学習をリセットし続けている

9.2 LP設計に反映すること

  • Google用とMeta用でFVの入り方を分ける（答えから始める 対 場面から始める）。骨格は1本でよい
  • Meta配信のコピーから "other" 相当語と二人称疑問形を消す。属性の帰属先をサービス側へ移す
  • インスタントフォームを使っているなら、LPフォームへの移行を検討する
  • 月間予算 ÷ 許容CPA が30未満なら、LPを増やさず中間CVを足す
  • P-MAXの拡張をオンで使うなら、LP上の画像の権利と表現を広告利用前提で点検する

9.3 提案資料の書き方を直すこと

  • 「PASONAの法則に基づき」と書くなら年を添える（2016年＝PASONA、2021年＝PASBECONA）
  • 「ホールが提唱したAIDMA」と書かない
  • 「漢字率3割」を指針として使わない
  • 「LPを直せばCPCが下がる」と断定しない（経路は説明できるが数値は公式に言えない）
  • 他社CVRベンチマークとの比較でLPの良し悪しを判断しない（日本市場に使えるデータは存在しない）
  • ABテスト事例を引くなら「条件不明」と併記する（国内50件中、期間と母数の両方が明記されていたのは1件のみ）

10. 残る未解決
